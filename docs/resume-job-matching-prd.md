# BOSS 求职助手简历匹配 PRD

版本 0.1 · 待评审 · 2026-11-24

## 1. 背景与目标

工作台目前按固定关键词在 BOSS 直聘搜索，再检查岗位标题、标签和描述是否命中关键词。这能帮助求职者缩小范围，但容易漏掉标题不同、职责相近的岗位，也无法解释一条岗位与哪段实际经历相符。

本功能面向使用本机工作台和 `boss-hiring` 助手的求职者。用户提供简历后，系统从简历提取有原文依据的能力，生成可编辑的搜岗方向，对已采集或新采集的真实岗位排序，并逐条说明匹配依据、能力缺口和待确认条件。用户可以从推荐结果勾选岗位，沿用工作台现有的清单确认流程。

首版继续使用本地 Mac 单账号工作台，城市限定杭州、上海，优先覆盖 AI 应用、大模型应用和 Agent 工程等已讨论的方向。城市是当前范围，搜索方向由实际简历内容生成并由用户确认。

## 2. 首版范围

- 在工作台粘贴简历文本，预览并修正提取结果，保存一份当前简历。
- 设置求职偏好，生成、编辑和确认本次搜索方向与关键词。
- 支持两种任务入口：匹配现有岗位库，或更新岗位后匹配。两种入口使用同一套排序规则。
- 展示推荐列表、原文依据和待核对条件，支持多选并生成投递清单草稿。
- 支持从 MausBot 发起匹配、查询进度和查看已生成的推荐结果。

PDF、Word 和扫描件解析，多份简历并行匹配，跨平台搜岗，自动改写简历，自动定时投递留作后续需求。未导入简历时，用户可继续使用现有关键词流程。

## 3. 用户流程

1. 打开工作台的「简历匹配」，粘贴简历文本并点击「提取经历」。
2. 查看提取结果与简历原文，修正经历字段，设置城市、公司排除、薪资下限以及对外包的态度。城市默认杭州和上海，薪资下限默认未设置，外包默认待确认。
3. 查看系统生成的搜索方向和关键词，按需要删改。选择「匹配现有岗位」或「更新岗位并匹配」。本次确认的关键词只用于本次匹配任务。
4. 查看推荐列表，按城市或推荐等级筛选，展开原文依据。用户可以跳过某条结果，或勾选多个岗位进入清单草稿。
5. 在现有清单页确认岗位、招聘者、发送动作和内容，再选择演练或真实执行。在 MausBot 发起的匹配也使用同一套清单确认流程。

## 4. 功能需求

### 4.1 简历与偏好

- 提取技能、项目经历、项目职责、成果、明确写出的工作年限和学历。每项提取结果保留对应简历原文。缺失信息显示「未填写」。
- 用户可修正提取结果。无法与简历原文对应的补充信息标为「用户补充」，可用于生成搜索词或提示用户核对。只有简历原文支持的内容可显示为「简历有证据」。
- 城市和排除公司是硬条件。薪资下限只有在用户设置后才生效。外包可选择「接受」「排除」或「待确认」。用户选择「排除」时，岗位明确标注外包才直接过滤，信息不足时标记待核对。
- 保存后生成简历版本。替换简历或修改偏好后，旧推荐显示「需重新匹配」，保留当次依据供对照。用户可删除简历及关联的推荐记录。

### 4.2 搜索与岗位来源

- 搜索方向从简历中明确出现的项目职责和能力推导。每个方向展示生成依据与建议关键词，用户可编辑后再启动采集。
- 「匹配现有岗位」读取工作台已入库且具有真实来源的岗位，不依赖新的 BOSS 登录或采集。使用项目现有导入入口的岗位同样可以参与匹配。
- 「更新岗位并匹配」复用现有采集服务。它按本次关键词和城市搜索，再合并新入库岗位与已有岗位，按 BOSS 岗位 ID 去重。每条推荐绑定可追溯的实际岗位记录和原始链接。
- 登录失效、出现验证或采集受阻时，展示具体阻塞状态。已有岗位可继续排序，结果页明确标注「仅基于已有岗位」和采集时间。候选范围受实际搜到并入库的岗位限制。
- 首版沿用工作台已有采集上限。排序时先检查库内可用岗位，再对初筛后的最多 50 条候选做语义判断。50 条为试用默认值，评测后可调整。

### 4.3 匹配与排序

每条岗位先经过硬条件检查，再逐项比较 JD 与简历。硬条件由程序判断，模型负责提取和比较文本。模型输出的每一条「有证据」结论必须具备可回查的简历片段和 JD 片段。

| 判断项 | 判定方式 | 展示或处理 |
| --- | --- | --- |
| 城市、排除公司 | 核对岗位实际城市和已配置的排除规则 | 明确不符的岗位移出推荐。城市缺失时标记待核对，保留查看入口 |
| 薪资、外包 | 根据用户设置检查岗位明确披露的信息。薪资统一到可比较的月固定薪资口径 | 薪资上限低于下限时过滤，区间跨过下限、口径不可比或关键字段缺失时标记待核对 |
| 核心职责及必备条件 | 对照两侧原文，区分「有证据」「部分相关」「待确认」「明确不符」 | 优先有相关项目实战依据的岗位。明确存在关键缺口的岗位降级并说明原因 |
| 加分项 | 比较相关工具、行业和项目场景 | 用于同等级岗位排序，单独展示 |

列表按「优先看」「可考虑」「需核对」呈现。先移除已知硬条件不符的岗位，再将关键硬条件或明确必备要求缺少证据的岗位标为「需核对」。其余岗位中，核心职责有明确证据且关键要求无明确冲突的列为「优先看」，职责部分相符或有明确能力缺口的列为「可考虑」，并列明缺口。列表同级先比较核心职责证据覆盖，再比较加分项，仍相同时按采集时间与岗位 ID 稳定排序。

示例：JD 写「独立交付企业 Agent 应用」，简历写「实现多步工作流、接入业务系统并上线」，系统可列出两段原文作为职责匹配依据。JD 同时要求「具备模型训练经验」，简历未提及该能力时，该项显示「待确认」。

### 4.4 推荐列表与投递清单

- 每张推荐卡显示职位、公司、实际城市、薪资、原始链接、采集时间、推荐等级和简短原因。详情可查看证据、缺口、待核对项和已有沟通状态。
- 推荐列表允许多选。只因旧固定关键词未命中的岗位，在简历匹配入口可经用户勾选进入草稿，前提是通过其余适用检查。实际城市无法核实或已知硬条件不符的岗位不能进入草稿。薪资或外包等未确认字段需在草稿预览明示。普通关键词入口沿用原筛选规则，后续执行沿用查重、岗位与招聘者核验、暂停、额度及网页确认。
- 结果进入草稿后沿用现有快照机制。岗位信息在确认后发生变化时，在执行前重新核对并按现有规则处理。岗位关闭或无法核实的项目不能发送。
- 本功能只把用户勾选的岗位送入草稿。正式发送仍须通过现有网页确认，演练结果单独展示。

### 4.5 MausBot 入口

- 用户可以要求 `boss-hiring` 使用工作台已保存的简历发起匹配，或查询最新推荐与进度。指令返回任务状态、岗位摘要与工作台入口。
- 缺少可用简历时，引导用户去工作台填写。MausBot 使用简历版本标识和必要的推荐摘要，简历原文在工作台管理。匹配入口负责生成推荐，执行入口只接收已确认清单。

## 5. 数据、异常与产品约束

- 每次任务记录简历版本、偏好、搜索词、参与匹配的岗位版本、规则版本及结果。简历更新或岗位描述变化时，可识别并重算受影响的匹配。
- 简历和岗位内容作为待分析数据。提取及排序模块只有读取资料、写入推荐结果的权限，真实沟通由现有执行任务处理。
- 简历默认保存于本机工作台的数据目录。若配置外部模型，调用前提示处理范围，对发出的文本移除手机号、邮箱等匹配无关信息。任务日志只记录状态和错误摘要。删除简历一并清理其推荐及引用缓存，独立保存的投递记录按现有工作台规则保留。
- 简历为空或无法提取有效经历时提示编辑。模型不可用、返回结果不完整或证据校验失败时，展示失败项并允许重试。可同时查看基础关键词筛选结果，语义结果待补齐。候选不足时按实际数量展示。

## 6. 验收标准

| 场景 | 验收结果 |
| --- | --- |
| 未导入简历 | 原关键词搜岗和原清单流程可正常使用。简历匹配入口提示填写简历 |
| 导入和修改简历 | 能查看关键经历的原文。简历没写的能力不会标为有证据。替换简历后旧推荐标记为需重新匹配 |
| 职称不同、职责相近 | 含工作流交付证据的简历，能找回并推荐至少一条基线关键词未命中、经人工确认合适的岗位。该岗位通过适用检查后可以进入清单草稿 |
| 硬条件及缺失信息 | 城市或排除公司明确不符的岗位不会进入推荐列表。薪资或必备条件缺少证据时显示对应待核对项 |
| 证据可追溯 | 抽查推荐理由中的简历与 JD 引用，均可在对应版本原文中找到。虚构技能或经历记为验收失败 |
| 采集受阻或离线 | 能使用已有岗位完成匹配，并清楚标注数据范围和采集时间 |
| 清单与发送状态 | 匹配、查看结果、创建草稿三个操作均不会产生真实沟通。网页确认后，只有清单内岗位可以交给执行流程 |
| MausBot 一致性 | `boss-hiring` 查询的推荐任务和结果与工作台一致，查询结果只包含推荐摘要及必要证据 |

首轮评测建议使用 **1 份脱敏简历和 30–50 条真实 JD**，包含职责相近但未命中旧关键词、技能词相似但职责不同、以及硬条件缺失的样本。由用户预先标注岗位「愿意投」「可考虑」「不会投」。在同一候选库上比较旧关键词结果与新排序的前 10 条，记录人工判为「愿意投」的数量、推荐依据错误数，以及新方案找回的合适岗位。基线有足够候选时，两组都评 10 条，实际不足时同步报告返回数。建议通过条件为前 10 条愿意投的数量不低于基线、至少找回 1 条人工确认的漏项、证据错误和硬条件违规为零。它只衡量本次样本，后续用更多简历和 JD 再校准规则。

真实采集验收单列。先通过导入岗位完成匹配、展示和草稿流程的验收。BOSS 登录及安全验证完成后，再用杭州、上海各一组搜索确认实际采集和新推荐链路。验收使用演练，真实投递以用户实际确认的任务单独核验。

## 7. 交付顺序

1. **已有岗位可匹配。** 完成简历录入、偏好设置、证据校验、排序和评测基线。
2. **能发现新岗位。** 接入按简历生成的搜索方向，复用采集和现有清单流程，验证关键词相近之外的岗位可以进入候选。
3. **MausBot 可管理。** 接入发起匹配、查询进度与推荐摘要，与网页同一任务结果对照验收。

现有工作台背景见 [README](../README.md)，采集、岗位和确认接口见 [工作台接口约定](api-contract.md)。
